# New TMS — Centralized Logging and Observability

The repository now has a centralized @tms/observability package for structured JSON logs and recursive redaction. API request telemetry uses this package. Existing durable audit persistence remains in audit_events.

## Standard envelope

- timestamp
- level
- event
- service
- environment
- request_id
- correlation_id
- tenant_id when available
- user_id when available

HTTP completion events include method, route, status code and duration.

## Levels

TRACE, DEBUG, INFO, WARN, ERROR and CRITICAL.

Production should normally use INFO or higher.

## Redaction

The centralized redactor masks authorization, access/refresh/id tokens, secrets, passwords, API keys, cookies/sessions, database URLs/connection strings and private keys.

## Correlation

X-Request-Id is bounded and generated by the existing request-context middleware. X-Correlation-Id is accepted separately and falls back to the request ID when absent.

## Tenant safety

Business/audit records retain tenant context when available and remain subject to PostgreSQL RLS. Infrastructure logs may be global.

## Audit persistence

Migration 0032_observability_audit_context.sql extends audit_events with correlation, Auth0 subject, network, user-agent and outcome fields. Existing RLS remains unchanged.

## Environment

The runtime consumes LOG_LEVEL and optionally LOG_SERVICE. No secret values are stored in documentation.

## Investigation flow

request_id → correlation_id → tenant_id → actor → event → audit/outbox/job → outcome.

Credentials must never be logged.
